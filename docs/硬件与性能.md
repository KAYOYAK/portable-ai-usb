## 纯生成速度

命令：

```powershell
llama-bench.exe -m <模型> -p 0 -n 48
```

| 后端 | 生成速度 |
|---|---|
| CUDA 13.4 | **62.07 tok/s** |
| Vulkan | **48.53 tok/s** |
| CPU | 3.43 tok/s |

**怎么读这几个数**：

- CUDA 和 Vulkan 都在 50 tok/s 以上 —— 远超"流畅"的体感阈值（30+）
- CPU 只有 3.4 tok/s —— **低于"能用"的底线**（10 tok/s 就开始难受）
- 换句话说：**这台机器上，CPU 模式只是"能跑起来"，不具备实用性**

### 参照的体感阈值

| 速度 | 体感 |
|---|---|
| < 10 tok/s | 明显卡顿，只能等 |
| 15 ~ 25 | 可以接受 |
| 30 ~ 60 | 流畅 |
| > 60 | 几乎即时 |

## 端到端（从插上 U 盘到能对话）

| 环节 | 耗时 |
|---|---|
| CUDA 引擎，冷启动（首次从 U 盘读模型） | ~52 秒 |
| CUDA 引擎，热启动 | ~10 秒 |
| Vulkan 引擎 | ~9 秒 |
| CPU 引擎 | ~5 秒 |
| 实际对话生成 | 17 ~ 33 tok/s |

**为什么 CPU 引擎反而最快加载**：它不需要初始化 CUDA 上下文、不需要分配显存、不需要把权重传上显卡。
它只是把模型 mmap 进来就开跑 —— 快，但是之后每一步都慢。

## 模型架构：为什么它这么省内存

MiMo-V2.6-Distill-Qwen-9B 的 `config.json` 里有个关键字段 —— `layer_types`：

```
32 层，每 4 层里有 1 层是 full_attention，剩下 3 层是 linear_attention
=> 只有 8 层需要真的存 KV 缓存
```

KV 缓存大小的算法：

```
每 token 的元素数 = 2(K和V) × 8(全注意力层) × 4(KV头) × 256(head_dim)
                  = 16384 个元素

f16  : 16384 × 2 字节 = 32768 字节/token ≈ 32 KB/token
q8_0 : ≈ 16 KB/token
q4_0 : ≈  8 KB/token
```

**8K 上下文只要约 256 MB**（f16）。

作为对比：Qwen3-8B（同样约 8B 参数）在 8K 上下文下要 **2.3 GB**。

差一个数量级。**这就是为什么这个模型特别适合"陌生电脑"场景** —— 你对那台机器的内存一无所知，
KV 缓存越小，能活下来的概率越大。

## U 盘速度的现实

| 介质 | 顺序读 | 4K 随机读 | 加载 6.4 GB |
|---|---|---|---|
| 普通 USB 3.0 闪存盘 | 100 ~ 150 MB/s | **1 ~ 5 MB/s** | 45 ~ 65 秒 |
| USB 3.2 Gen 2 闪存盘 | 200 ~ 400 MB/s | 5 ~ 20 MB/s | 17 ~ 30 秒 |
| 移动固态（NVMe） | 1000+ MB/s | 50+ MB/s | 2 ~ 3 秒 |

**真正的杀手是 4K 随机读**（闪存盘只有 1~5 MB/s）。加载模型是纯顺序读，所以问题不大 ——
但如果你打算频繁切换模型（每次都要重新读一遍权重），移动固态的体验会好很多。

### 内存与温度的坑

- **别让 KV 缓存超过物理内存的 20~30%**，否则开始换页，速度断崖式下跌
- U 盘持续读写会明显发热，**温度上去之后主控会降速**。长对话会让日志持续写入

## 参数速查

### 上下文长度（`-Ctx`）

| 显存 | 自动选的上下文 |
|---|---|
| ≥ 15 GB | 65536 |
| ≥ 11 GB | 32768 |
| ≥ 8 GB | 16384 |
| ≥ 6 GB | 8192 |
| > 0 但 < 6 GB | 4096（只卸载 20 层） |
| 纯 CPU | 8192 |

### 常见手动组合

```powershell
# 大显存，长文档
-Backend cuda -Ctx 65536 -Ngl 99

# 中等显存，均衡
-Backend cuda -Ctx 32768 -Ngl 99

# 小显存（6~8 GB），保守
-Backend cuda -Ctx 8192 -Ngl 20

# AMD / Intel / 老 N 卡
-Backend vulkan -Ngl 99

# 兜底，任何机器都能跑
-Backend cpu -Ngl 0 -Ctx 8192
```

### `-Ngl` 怎么调

`--n-gpu-layers` = 往显存里卸载多少层。

- `99` = 全都卸载（模型只有 32 层，99 是"全部"的惯用写法）
- `20` = 只卸载 20 层，显存占用能压到 4 GB 出头
- `0` = 一点不卸载，纯 CPU

显存不够就往下调，每降一档大约省 100~150 MB。

### 采样参数

启动器用的默认值：

```
--temp 0.6  --top-p 0.95  --top-k 20  --min-p 0
--reasoning-format deepseek
```

`--reasoning-format deepseek` 是为了让这个模型的推理过程（` thinking` 块）能被正确解析成单独的字段，
而不是混在回复正文里。

## 换一台电脑会怎样

| 那台电脑的情况 | 会走哪个后端 | 预期 |
|---|---|---|
| 有较新的 NVIDIA 独显 | CUDA | 快（30 ~ 60 tok/s） |
| 有 AMD / Intel 独显 | Vulkan | 较快（20 ~ 40 tok/s） |
| 只有核显、内存 16 GB+ | Vulkan 或 CPU | 慢但能用（3 ~ 10 tok/s） |
| 只有核显、内存 8 GB | CPU | 很慢（3 ~ 5 tok/s），但能跑 |
| 内存 8 GB 以下 | CPU | 会疯狂换页，基本不可用 |

**关键结论**：这套东西的可用性上限由**那台机器的显卡**决定，不是由 U 盘决定。
有独显就是好体验，没有就是能用但慢。

如果你需要保证"在任何电脑上都快"，那只有一个办法 —— **带一张显卡**。这是物理规律，不是软件能解决的。
