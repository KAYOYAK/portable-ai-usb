## 纯生成速度

命令：

```powershell
llama-bench.exe -m <模型> -p 0 -n 48
```

| 后端 | 生成速度 |
|---|---|
| CUDA 13.4 | **62.07 tok/s** |
| Vulkan | **48.53 tok/s** |
| CPU | 3.43 tok/s |

**怎么读这几个数**：

- CUDA 和 Vulkan 都在 50 tok/s 以上 —— 远超"流畅"的体感阈值（30+）
- CPU 只有 3.4 tok/s —— **低于"能用"的底线**（10 tok/s 就开始难受）
- 换句话说：**这台机器上，CPU 模式只是"能跑起来"，不具备实用性**

### 参照的体感阈值

| 速度 | 体感 |
|---|---|
| < 10 tok/s | 明显卡顿，只能等 |
| 15 ~ 25 | 可以接受 |
| 30 ~ 60 | 流畅 |
| > 60 | 几乎即时 |

## 端到端（从插上 U 盘到能对话）

| 环节 | 耗时 |
|---|---|
| CUDA 引擎，冷启动（首次从 U 盘读模型） | ~52 秒 |
| CUDA 引擎，热启动 | ~10 秒 |
| Vulkan 引擎 | ~9 秒 |
| CPU 引擎 | ~5 秒 |
| 实际对话生成 | 17 ~ 33 tok/s |

**为什么 CPU 引擎反而最快加载**：它不需要初始化 CUDA 上下文、不需要分配显存、不需要把权重传上显卡。
它只是把模型 mmap 进来就开跑 —— 快，但是之后每一步都慢。

## 模型架构：为什么它这么省内存

MiMo-V2.6-Distill-Qwen-9B 的 `config.json` 里有个关键字段 —— `layer_types`：

```
32 层，每 4 层里有 1 层是 full_attention，剩下 3 层是 linear_attention
=> 只有 8 层需要真的存 KV 缓存
```

KV 缓存大小的算法：

```
每 token 的元素数 = 2(K和V) × 8(全注意力层) × 4(KV头) × 256(head_dim)
                  = 16384 个元素

f16  : 16384 × 2 字节 = 32768 字节/token ≈ 32 KB/token
q8_0 : ≈ 16 KB/token
q4_0 : ≈  8 KB/token
```

**8K 上下文只要约 256 MB**（f16）。

作为对比：Qwen3-8B（同样约 8B 参数）在 8K 上下文下要 **2.3 GB**。

差一个数量级。**这就是为什么这个模型特别适合"陌生电脑"场景** —— 你对那台机器的内存一无所知，
KV 缓存越小，能活下来的概率越大。

## U 盘速度的现实

**这是整个方案里最硬的一道墙。** 模型是 6.4 GB 的一个大文件，每次启动都要整个读一遍。
盘快一点慢一点，直接决定你是等 50 秒还是等 5 分钟。

### 实测：本机那支盘

启动器每次启动都会实测一遍，菜单 `[11]` 也能单独测。

| 项目 | 实测（连测三次） |
|---|---|
| 顺序读 | **127.0 / 132.6 / 146.5 MB/s** |
| 随机 4K | **1,795 / 2,045 / 2,366 IOPS**（约 7 ~ 9 MB/s） |
| 冷启动加载 6.4 GB 模型 | **53.7 秒** |

同一台机器上，模型放在内置 NVMe 里加载只要 **约 5 秒**。
**10 倍差距，全部来自盘。**

> 启动器报的"预计加载约 N 秒"就是按实测顺序读算的：64 MB 读两次取较慢的，
> 再按模型体积换算。用本机数据回验：预估 50 ~ 57 秒 vs 实测 53.7 秒。

### 分档

| 介质 | 顺序读 | 4K 随机读 | 加载 6.4 GB |
|---|---|---|---|
| 移动固态（NVMe） | 1000+ MB/s | 50+ MB/s | 2 ~ 3 秒 |
| USB 3.2 Gen 2 闪存盘 | 200 ~ 400 MB/s | 5 ~ 20 MB/s | 17 ~ 30 秒 |
| **USB 3.x 闪存盘（本机实测）** | **127 ~ 146 MB/s** | **7 ~ 9 MB/s** | **约 54 秒** |
| 老 USB 3.0 廉价盘 | 60 ~ 120 MB/s | 1 ~ 3 MB/s | 1.5 ~ 2 分钟 |
| USB 2.0 口 / 极廉价盘 | 25 ~ 40 MB/s | < 1 MB/s | 4 ~ 5 分钟 |

**除加粗那一行，其余是按接口带宽推算的量级，不是本机测量结果。**
你自己那支盘的真实数字，菜单 `[11]` 测一次比看这张表准。

**为什么两个速度都要看**：顺序读决定"读完 6.4 GB 要多久"；随机 4K 决定"读的过程中卡不卡"。
闪存盘的随机 4K 通常只有顺序读的 **1/20** —— 这是它和固态盘的本质差距，
也是"SSD 能用、U 盘很慢"不是错觉的原因。

### 怎么挑盘

- **移动固态（PSSD）优先。** 不必买旗舰，几百块那种的速度已经远超闪存盘。
- 真买 U 盘：认 **USB 3.2 Gen1 及以上**，避开一二十块的无名盘，容量 **≥ 32 GB**
  （现在占用约 8 GB，留出空间给 `models\` 里的第二个模型）。
- **不用**为 1000 MB/s 的旗舰多花钱 —— 瓶颈在 USB 3.x 接口本身，多花的钱感受不到。
- **不用**为了速度特意换 Type-C 盘，除非你确定目标电脑有 Type-C 口。

### 插哪个口

同一支盘换个口，速度能差好几倍。顺序：

1. **蓝色 USB 3.x 口**（或标着 `SS` / `10` / `20` 的口）
2. 机箱背后的口（直连主板，比前置面板稳）
3. 避开 USB Hub、扩展坞、显示器上的口 —— 尤其是不带独立供电的 Hub

测速明显低于预期（比如只有 30 MB/s）时，**先换个口重插再测一次**，再怀疑是盘的问题。

### 卡和慢不是一回事

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 加载慢（几十秒到几分钟） | 盘或接口的带宽 | 菜单 `[11]` 测一下，换个口重试 |
| 加载完了但对话卡 | 显卡或内存不够 | 菜单 `[3]` 省显存 / `[5]` 纯 CPU |
| 加载中卡住不动 | 盘上有坏块，或掉盘 | 换盘。硬件问题，改参数救不回来 |
| 加载慢且风扇狂转 | 内存太小，系统在换页 | 见下条 |

内存不够时会**换页**，表现和"盘慢"很像但更严重。如果是这种情况，可以试菜单 `[12]`
（不用 mmap 启动，整块读进内存）。装不下的话启动器会改回 `auto` 并说明原因。

### 内存与温度的坑

- **别让 KV 缓存超过物理内存的 20~30%**，否则开始换页，速度断崖式下跌
- U 盘持续读写会明显发热，**温度上去之后主控会降速**。长对话会让日志持续写入

## 参数速查

### 上下文长度（`-Ctx`）

| 显存 | 自动选的上下文 |
|---|---|
| ≥ 15 GB | 65536 |
| ≥ 11 GB | 32768 |
| ≥ 8 GB | 16384 |
| ≥ 6 GB | 8192 |
| > 0 但 < 6 GB | 4096（只卸载 20 层） |
| 纯 CPU | 8192 |

### 常见手动组合

```powershell
# 大显存，长文档
-Backend cuda -Ctx 65536 -Ngl 99

# 中等显存，均衡
-Backend cuda -Ctx 32768 -Ngl 99

# 小显存（6~8 GB），保守
-Backend cuda -Ctx 8192 -Ngl 20

# AMD / Intel / 老 N 卡
-Backend vulkan -Ngl 99

# 兜底，任何机器都能跑
-Backend cpu -Ngl 0 -Ctx 8192
```

### `-Ngl` 怎么调

`--n-gpu-layers` = 往显存里卸载多少层。

- `99` = 全都卸载（模型只有 32 层，99 是"全部"的惯用写法）
- `20` = 只卸载 20 层，显存占用能压到 4 GB 出头
- `0` = 一点不卸载，纯 CPU

显存不够就往下调，每降一档大约省 100~150 MB。

### 采样参数

启动器用的默认值：

```
--temp 0.6  --top-p 0.95  --top-k 20  --min-p 0
--reasoning-format deepseek
```

`--reasoning-format deepseek` 是为了让这个模型的推理过程（` thinking` 块）能被正确解析成单独的字段，
而不是混在回复正文里。

## 换一台电脑会怎样

| 那台电脑的情况 | 会走哪个后端 | 预期 |
|---|---|---|
| 有较新的 NVIDIA 独显 | CUDA | 快（30 ~ 60 tok/s） |
| 有 AMD / Intel 独显 | Vulkan | 较快（20 ~ 40 tok/s） |
| 只有核显、内存 16 GB+ | Vulkan 或 CPU | 慢但能用（3 ~ 10 tok/s） |
| 只有核显、内存 8 GB | CPU | 很慢（3 ~ 5 tok/s），但能跑 |
| 内存 8 GB 以下 | CPU | 会疯狂换页，基本不可用 |

**关键结论**：这套东西的可用性上限由**那台机器的显卡**决定，不是由 U 盘决定。
有独显就是好体验，没有就是能用但慢。

如果你需要保证"在任何电脑上都快"，那只有一个办法 —— **带一张显卡**。这是物理规律，不是软件能解决的。
