# 杀毒软件误报 / 被拦截

## 一句话

**这个项目里没有任何病毒。** 会被拦，是因为它的行为模式——
「一支 U 盘里的未签名 exe，插上就启动、监听本地端口、还去读一个 6 GB 的大文件」——
和某些恶意软件确实长得像。

所有代码都在这个仓库里，是明文，可以直接读。没有混淆、没有下载执行、没有编码过的字符串。

---

## 会被盯上的是哪几样

| 文件 | 为什么触发 |
|---|---|
| `llama.cpp\*\llama-server.exe` | 未签名的独立 exe，启动后**监听 TCP 端口**。启发式引擎对「未签名 + 监听端口」最敏感。**这是最常被报的一个。** |
| `启动AI.bat` / `高级选项.bat` | 批处理调用 PowerShell。特别是 `-ExecutionPolicy Bypass` 这个参数 —— 它是常见恶意载荷的写法。我们用它的原因很单纯：默认执行策略会拦住未签名脚本。 |
| `launcher.ps1` / `tools\*.ps1` | 同上。 |
| `ggml-cuda.dll` / `ggml-vulkan.dll` 等 | 体积大、未签名的原生 DLL。有些引擎会直接标记「未知发布者的大 DLL」。 |

---

## 三个你可以自己核实的点

不用信上面的说法，自己验：

### 1. 它只监听本机，不是整个局域网

启动参数里写死了 `--host 127.0.0.1`，不是 `0.0.0.0`。局域网里别的机器连不上来。

启动后自己看：

```cmd
netstat -ano | findstr 8080
```

监听地址那一列应该是 `127.0.0.1:8080`，不是 `0.0.0.0:8080`。

### 2. 它不往外连

除了你浏览器打开的本地页面，没有任何出站请求。

**断网跑一次就知道了** —— 功能完全一样。这也是这个项目的核心卖点，顺便就成了最好的清白证明。

### 3. 产物全在 U 盘里

日志写进 `U盘\logs\`，模型缓存由环境变量指回盘内。
宿主系统上不会留下东西，除了浏览器的一次访问记录。

## 怎么加白名单

### Windows Defender

**临时**：弹窗里点「允许在设备上」。

**永久**（图形界面）：
1. 设置 → 隐私和安全性 → Windows 安全中心 → 病毒和威胁防护
2. 「病毒和威胁防护」设置下点「管理设置」
3. 拉到底，「排除项」→「添加或删除排除项」
4. 选「文件夹」，添加 U 盘上的 `llama.cpp` 目录

> 只排除 `llama.cpp` 目录就够了，不需要排除整支 U 盘。

**永久**（管理员 PowerShell，把 `X` 换成 U 盘盘符）：

```powershell
Add-MpPreference -ExclusionPath "X:\llama.cpp"
```

撤销：

```powershell
Remove-MpPreference -ExclusionPath "X:\llama.cpp"
```

查看当前排除项：

```powershell
Get-MpPreference | Select-Object -ExpandProperty ExclusionPath
```

### 第三方杀软

360、火绒这类通常会在弹窗里给「信任 / 放行 / 加入白名单」，选一次即可。

如果它**直接删掉了文件**：去「隔离区」恢复并加白，然后重跑一遍 `tools\准备U盘.ps1`
把被删的文件补回来（它是幂等的，已有的会跳过或校验后重下）。

## 企业受管电脑：这一类加白名单也没用

先分清是**误报**还是**策略禁止**：

| | 误报 | 策略禁止 |
|---|---|---|
| 症状 | 弹窗提示、文件被隔离 | 双击**毫无反应**，或弹出「已被系统管理员阻止」 |
| 事件查看器 | 杀软自己的日志 | AppLocker / WDAC 的阻止记录 |
| 加白名单 | 有效 | 无效，需要 IT 改策略 |

具体情况：

- **AppLocker / WDAC**：公司策略禁止从可移动介质执行程序。这是**策略层面**的限制，
  不是误报，本机改不了。
- **受管 EDR**（Defender ATP、CrowdStrike 等）：白名单由 IT 集中下发，本机改不动。

所以如果你在评估「能不能在公司的电脑上用」，**先看 [README 的「已知限制」](../README.md)** 再往下走 ——
受管电脑通常不只在一道关卡上拦下来。

## 为什么不做代码签名

- 代码签名证书一年几百到上千美元；
- 更根本的是：这支 U 盘里的 exe **全部来自 llama.cpp 官方发布**，不是本项目编译的。
  给别人的二进制签名没有意义，也不该由本项目来签。

**想自己确认 exe 的来源**：`tools\准备U盘.ps1` 在下载时校验 SHA-256，
哈希写在脚本里；下载地址指向 llama.cpp 官方 release，可以拿官方页面的 digest 对照。

## 报告误报

如果你觉得某个文件的检测结果值得上报：

- Microsoft：<https://www.microsoft.com/en-us/wdsi/filesubmission>
- 国内杀软厂商一般都有「误报申诉」入口，搜「厂商名 + 误报申诉」

上报时附上**你从 GitHub 下载回来的文件的哈希**，比附文件本身更有用 ——
对方能直接确认你手上那份和仓库里那份是不是同一份。

## 最后

真被拦了，多半只是麻烦一下。**唯一需要当真的情况是**：
杀软不仅拦截、还**把文件删了或隔离了**，那 U 盘就不完整了，
重跑一遍 `tools\准备U盘.ps1` 或 `[9] 环境自检` 确认一下缺了什么。
