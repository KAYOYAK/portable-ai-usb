按"症状"找。

## 启动相关

### 双击 `启动AI.bat` 窗口一闪就没了

先手动开一个 PowerShell，把命令敲进去看报错：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "E:\launcher.ps1"
```

（把 `E:` 换成你 U 盘的实际盘符）

最常见的原因：**PowerShell 执行策略**把脚本拦下了。`.bat` 里已经带了 `-ExecutionPolicy Bypass`，
但如果你手动跑 `.ps1` 就会撞上。加 `-ExecutionPolicy Bypass` 即可。

### 提示「缺少 VCRUNTIME140.dll」/「缺少 MSVCP140.dll」

`llama-server.exe` 本身只有 9 KB，是个 import stub，真正的实现在 `ggml*.dll` + 微软的 C++ 运行库里。

正确做法是**把运行库跟 exe 放一起**（app-local），这样不碰宿主系统。需要这 10 个：

```
vcruntime140.dll          vcruntime140_1.dll        vcruntime140_threads.dll
msvcp140.dll              msvcp140_1.dll            msvcp140_2.dll
msvcp140_atomic_wait.dll  msvcp140_codecvt_ids.dll
concrt140.dll             vcomp140.dll
```

它们本来在 `C:\Windows\System32\`。跑一遍 `tools\准备U盘.ps1` 会自动补上。

**为什么不用装 VC++ Redistributable**：在别人的电脑上装软件是需要管理员权限的，
而且装完就留下痕迹了。app-local 是另一条路 —— Windows 的 [DLL 搜索顺序](https://learn.microsoft.com/zh-cn/windows/win32/dlls/dynamic-link-library-search-order)
里，**exe 所在目录的优先级高于 System32**，所以放在一起就会被优先加载。

验证方法（能看出 DLL 到底是从哪儿加载的）：

```powershell
Get-Process llama-server | ForEach-Object { $_.Modules } |
  Where-Object { $_.FileName -like "E:\*" } |
  Select-Object ModuleName, FileName
```

### 提示「端口已被占用」

启动器会先探测 8080：

- 如果占用者是**本 U 盘的 AI**（通过 `/props` 的 `model_path` 判断），它会直接帮你打开页面
- 如果是**别的程序**，它会自动往后找 8081、8082……直到找到空闲端口

注意：**默认端口以后会变**。llama.cpp 的日志里已经写了
`server default port will be changed to :9931 in a future release`。本项目显式传 `--port`，不受影响。

## 性能相关

### 明明有显卡，为什么还是慢？

看启动器输出的「已选后端」那一行：

- `NVIDIA CUDA 13.4` = 走显卡了
- `Vulkan` = 走显卡了（但不是最优路径）
- `纯 CPU` = **没走显卡**，这就是慢的原因

走 CPU 的常见理由：

1. **没有 NVIDIA 显卡** → CUDA 版本直接跳过。AMD / Intel 卡走 Vulkan
2. **显卡驱动太老** → CUDA 13.4 需要比较新的驱动。可以试试 Vulkan
3. **`nvidia-smi` 不在 PATH 里** → 启动器读不到显存，会退回保守配置
4. **是台笔记本且用的是核显输出** → 有些机器独显被禁用或没装驱动

想看 CUDA 到底认没认出来，直接问引擎：

```powershell
& "E:\llama.cpp\cuda13\llama-server.exe" --list-devices
```

正常应该看到：

```
Available devices:
  CUDA0: NVIDIA GeForce ... (12199 MiB, 11042 MiB free)
```

### 报 CUDA out of memory / 显存不够

用 `高级选项.bat`：

- **[3] 省显存**（8K 上下文）
- 或者 **[4] Vulkan** / **[5] 纯 CPU**

启动器会按显存自动算上下文，但它的估计是保守的 —— 如果你同时开着浏览器、
游戏或者别的吃显存的东西，实际可用显存会比它以为的少。

想手动控制，直接调参数：

```powershell
powershell -File "E:\launcher.ps1" -Backend cuda -Ctx 4096 -Ngl 20
```

`-Ngl` 是往显存里卸载多少层。**实测这台 12 GB 卡：`-ngl 20` 能把显存占用压到 4 GB 出头。**

### 卡到几乎不能用

先看内存。**模型走 mmap，不需要整份塞进内存也能跑 —— 但内存越紧，换页越多，越卡。**

经验门槛：**内存 ≥ 模型大小 + 1.5 GB** 才舒服。

启动器会自动降级：内存紧张时把上下文压到 16K，非常紧张时压到 8K 并把 KV 缓存精度降到 q4_0。

如果还是很卡，直接用 `[5] 纯 CPU` —— 它可以更激进地用 mmap，反而比硬塞进显存稳。

### 提示 `Illegal instruction` / 一启动就崩

这是 **CPU 指令集不匹配**。某些项目发布的是用 `-DGGML_NATIVE=ON` 编译的本机优化版，
拿到别的 CPU 上就会因为执行了不支持的指令而崩。

**llama.cpp 的官方 Windows 包不是这样**：它用
`-DGGML_CPU_ALL_VARIANTS=ON -DGGML_NATIVE=OFF -DGGML_BACKEND_DL=ON` 编译，
解压出来有 14 个 `ggml-cpu-*.dll`（`sandybridge` 到 `zen4`），
运行时自动挑匹配当前 CPU 的那个加载。

如果你拿到的包解压后**没有** `ggml-cpu-*.dll`，那就是有人自己编译的单架构版本 —— 换官方包。

## 系统相关

### Windows 11 S 模式

S 模式只允许从 Microsoft Store 装应用，**非商店程序会被拒绝运行**。
需要先在「设置 → 系统 → 激活」里退出 S 模式（一次性，不可逆）。

### SmartScreen 弹窗「Windows 已保护你的电脑」

理论上不会出现 —— **exFAT / FAT32 分区不支持 NTFS 附加数据流（ADS）**，
所以从 U 盘拷来的文件不会带"来自 Internet"标记，SmartScreen 也就没理由拦。

想确认：

```powershell
Get-Item "E:\启动AI.bat" -Stream *
```

如果只列出 `:$DATA`，说明没有 ADS 标记。

万一还是弹了，点「更多信息 → 仍要运行」，或者先解除：

```powershell
Get-ChildItem E:\ -Recurse | Unblock-File
```

### 公司电脑，双击没反应 / 提示被策略阻止

企业受管电脑如果启用了 **AppLocker** 或 **WDAC**，会禁止从可移动介质执行程序。
这是**策略层面的限制**，不是技术问题 —— 绕不过去，也不该绕。

同理，如果组策略禁用了 PowerShell 或者限制了执行策略，`.ps1` 也跑不起来。

### 杀毒软件报毒

`llama-server.exe` 是个才 18 MB 的推理服务，偶尔会被启发式规则误报。
加白名单即可。这也正是**用官方发布包**的意义 —— 有明确的来源可以核对。

### 会不会在别人的电脑上留东西？

默认行为：

- 日志写 `U盘\logs\`
- 模型和 KV 缓存都在 U 盘上
- **不写宿主机的用户目录，不装任何东西**

但有两处例外，它们**不由本项目控制**：

1. Windows 自己会在 U 盘根目录建 `System Volume Information\`（系统卷信息）
2. 宿主机的「最近使用的文件」可能会记一笔

想更干净，用 `[7] 停止本 U 盘的 AI` 正常停掉再拔盘。

## 使用相关

### 怎么换模型？

把新的 `.gguf` 丢进 `models\` 目录。启动器会**自动挑最大的那个**用。
不想要旧的就把旧的删掉。

想让启动器用一个特定的模型，最省事的做法是 `models\` 里只放一个。

### 怎么换量化版本？

同一个模型的不同量化就是不同大小的 `.gguf`：

| 量化 | 大小 | 质量 | 适合 |
|---|---|---|---|
| Q4_K_M | 5.44 GB | 够用 | 8 GB 内存 / 小显存 |
| **Q5_K_M** | **6.40 GB** | **好（推荐）** | **16 GB 内存 / 12 GB 显存** |
| Q8_0 | 8.89 GB | 接近无损 | 显存充裕 |

Q4 比 Q5 大概省 1 GB，质量损失在多数对话里感觉不出来。
**别用 Q2 / Q3** —— 省下的空间不值得质量损失。

### 能不能在 macOS / Linux 上跑？

**这套脚本不行**，它是 Windows 专用的（PowerShell + `.bat`）。
llama.cpp 本身跨平台，模型文件（GGUF）也是通用的 —— 在 Mac/Linux 上单独装一个 llama.cpp 指向同一个 `.gguf` 就行。

### U 盘能拔吗？

**AI 运行期间不要拔。** 引擎正在从 U 盘读模型权重，拔了会直接崩溃。

正确顺序：`[7] 停止本 U 盘的 AI`（或关掉那个窗口）→ 等提示停止 → 拔盘。

### 模型加载为什么这么慢？

冷启动要从 U 盘读 6.4 GB。普通 USB 3.0 闪存盘的顺序读大概 100~150 MB/s，
所以 **40~60 秒**是正常的。热启动（系统文件缓存还在）能快到 10 秒左右。

真正的瓶颈不是顺序读，而是 **4K 随机读**（闪存盘只有 1~5 MB/s）。
好在加载模型是纯顺序读，所以问题不大。

换成移动固态的话，能压到 2~3 秒。

powershell -ExecutionPolicy Bypass -File "E:\tools\自检.ps1"
